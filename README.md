# 🛡️ AI Security Roadmap

## From zero to your first AI security role, in 12 weeks

**By [@cyberwithshruti](https://instagram.com/cyberwithshruti)**

Cybersecurity education for B.Tech students, freshers and career switchers.

---

## ✨ Start here

AI security is not a shortcut around cybersecurity basics. It is a layer you build on top of them.

This roadmap gives you 4 stages, in order, and a 12-week plan to move through them.

- 🎯 **Who it is for:** B.Tech students, freshers, career switchers new to security
- 🧰 **What you need:** A laptop, 6 to 8 hours a week, free accounts on the platforms below
- 📌 **The rule:** Finish the foundation first, or the AI-specific topics won't make sense

> 💡 **Why now?** Companies are putting chatbots, assistants and AI agents into their products, and attackers are starting to use AI agents too. Defenders who understand both sides will be useful.

---

## 🗺️ The 4 stages

1. 🧱 **Foundations** (weeks 1 to 4)
2. 🐍 **Python** (weeks 5 to 6)
3. ☁️ **Cloud basics** (weeks 7 to 8)
4. 🤖 **AI Security** (weeks 9 to 12)

---

## 🧱 Stage 1: Foundations (weeks 1 to 4)

Networking, Linux and OS basics come first. Every security tool and every AI system runs on top of them.

### 🌐 Networking

- **Learn:** OSI and TCP/IP, IP addressing and subnets, DNS, HTTP/HTTPS, TCP vs UDP, firewalls
- **Free resources:** Professor Messer Network+ videos (YouTube), TryHackMe Pre Security path

### 🐧 Linux

- **Learn:** File system, permissions, users, processes, package managers, shell commands
- **Free resources:** [OverTheWire Bandit](https://overthewire.org/wargames/bandit/), TryHackMe Linux Fundamentals

### 🪟 OS basics

- **Learn:** Windows vs Linux, processes and services, logs, authentication
- **Free resources:** TryHackMe Windows Fundamentals

✅ **Checkpoint:** You can explain what happens when you type a website address into a browser, and move around a Linux terminal without a GUI.

---

## 🐍 Stage 2: Python for security (weeks 5 to 6)

Python automates the boring parts of security work, and most AI tools are built in it.

- **Learn:** variables, loops, functions, files, lists and dictionaries, the `requests` library
- **Then:** reading JSON, the command line, calling an AI model through its API

### Three portfolio projects

1. 🔍 **Port scanner** that checks open ports on your own machine
2. 📜 **Log analyzer** that counts failed login attempts by IP address
3. 🔑 **Password strength checker** that flags weak patterns

✅ **Checkpoint:** You can write a 50-line script that reads a file, finds a pattern and prints a summary.

---

## ☁️ Stage 3: Cloud security basics (weeks 7 to 8)

Most AI systems run in the cloud. Pick one provider, AWS or Azure, and stay with it.

- **Core ideas:** shared responsibility model, IAM, least privilege, storage permissions, logging and monitoring
- **Mistakes to understand:** public storage buckets, over-permissioned accounts, leaked access keys
- **Optional entry-level certificate:** AWS Cloud Practitioner or Microsoft AZ-900 (check the provider's site for current details and fees)

✅ **Checkpoint:** You can explain why a public storage bucket is dangerous and how to apply least privilege to a new user.

---

## 🤖 Stage 4: AI security (weeks 9 to 12)

This is the specialty layer: how AI systems get attacked, and how to defend them.

- 💬 **Prompt injection:** tricking an AI into ignoring its rules. Practice: [Gandalf by Lakera](https://gandalf.lakera.ai)
- 🧨 **Insecure AI apps:** apps that trust model output, leak data or take unsafe actions. Read: [OWASP Top 10 for LLM Applications](https://genai.owasp.org)
- 🕹️ **AI agent risks:** agents with too many permissions can be steered into harmful actions. Practice: build a small agent and limit its tools
- 🧭 **Attack frameworks:** a catalog of how real attacks on AI systems are structured. Read: [MITRE ATLAS](https://atlas.mitre.org)

**Defender's mindset:** assume the model can be manipulated, limit what it can access, validate what goes in and out, and log what it does.

✅ **Checkpoint:** You can explain prompt injection to a non-technical friend and name three ways to reduce its impact.

---

## 🧪 Practice and proof of work

Recruiters trust what you built more than what you claim. Start a public record from week 1.

- 🎮 **Labs and CTFs:** [TryHackMe](https://tryhackme.com), Hack The Box, OverTheWire
- 🐙 **GitHub:** put every project there with a clear README
- ✍️ **Write-ups:** after each lab, write what you tried, what failed, what you learned
- 📣 **Learn in public:** share one learning a week on LinkedIn or Instagram
- 🤝 **Community:** join a cyber club or Discord so you are not learning alone

🏁 **Goal by week 12:** 3 GitHub projects, 3 write-ups, 1 AI security lab you can talk about in an interview.

---

## 📅 12-week study plan

- **Week 1:** Networking: OSI, TCP/IP, IP addressing → notes and a diagram of how a web request travels
- **Week 2:** Networking: DNS, HTTP, HTTPS, firewalls → TryHackMe Pre Security rooms completed
- **Week 3:** Linux commands and permissions → first 10 Bandit levels cleared
- **Week 4:** Linux and Windows basics, logs → a short post on what you learned
- **Week 5:** Python basics and files → log analyzer script
- **Week 6:** Python for security: requests, JSON → port scanner or password checker on GitHub
- **Week 7:** Cloud basics: IAM and least privilege → free-tier account set up safely
- **Week 8:** Cloud storage, logging, common mistakes → write-up on one cloud misconfiguration
- **Week 9:** Prompt injection basics → Gandalf levels completed and notes
- **Week 10:** OWASP Top 10 for LLM Applications → one-page summary in your own words
- **Week 11:** AI agent risks and MITRE ATLAS → small AI app or agent with limited permissions
- **Week 12:** Portfolio and visibility → clean GitHub, 3 write-ups, 1 public post
